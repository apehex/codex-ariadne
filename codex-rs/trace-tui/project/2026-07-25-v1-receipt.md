# Milestone receipt: first historical browser

Date: 2026-07-25  
Status: functional preview implemented; Linux integration validation recorded below

## Implemented

- `codex-trace` discovers ordinary sessions and rich bundle manifests without
  writing indexes or eagerly reducing every bundle.
- Ordinary, rich, and merged roots use source-namespaced stable locators,
  explicit capabilities, evidence grades, and navigable diagnostics.
- Broken or cyclic ordinary parent links remain reachable below the session and
  retain their recorded parent metadata.
- Rich raw payloads are opened lazily with canonical bundle containment,
  regular-file enforcement, a display-size cap, lossy UTF-8 handling, and
  terminal-control sanitization.
- `codex trace`, direct session selection, `--bundle`, `--trace-root`, and
  `CODEX_ROLLOUT_TRACE_ROOT` launch the offline read-only Ratatui browser.
- The TUI includes a searchable root picker, adaptive tree/children/inspector
  layouts, breadcrumbs, provenance and capability labels, selected-tree
  search, diagnostics, and collapsed raw payloads.
- Discovery, rich event replay, ordinary record retention, projected nodes,
  search fields, and search hits have explicit default limits. Reaching a
  limit leaves a visible diagnostic instead of silently implying completeness.
- Search runs on submission and reports the matching field, byte range,
  evidence grade, provenance, and a match-centered snippet.
- Malformed rich event spines retain usable nodes but downgrade their semantic
  evidence to `reconstructed`; reducer failures stop downstream best-effort
  replay because reducer handlers are not transactional.
- The existing rollout-trace reducer now truncates non-ASCII JSON summaries at
  a valid UTF-8 boundary and exposes manifest-only discovery metadata.
- Synthetic tracing proves that exact spawn and follow-up text is retained in
  opt-in raw tool/runtime payloads even when the child-side message is opaque.

## Validation

- `just test -p codex-rollout-trace`: 70 passed.
- `just test -p codex-trace`: 11 passed.
- `just test -p codex-trace-tui`: 6 passed with nine deterministic snapshots,
  including narrow, medium, and wide layouts.
- `just test -p codex-cli`: 318 passed, including the new trace subcommand
  parsing and conflict tests.
- Package-scoped `just fix` passed for `codex-trace` and `codex-trace-tui`.
- TUI read-only tests compare every synthetic ordinary rollout, rich manifest,
  event spine, and payload byte before and after discovery, loading, rendering,
  navigation, search, and lazy raw-payload inspection.
- Fork-wide CLI, lockfile, and build integration checks are recorded here after
  the final integration pass.

## Known limitations

- Ordinary rollouts do not provide exact per-generation context and may retain
  encrypted inter-agent content; the UI labels those source capabilities
  rather than reconstructing plaintext.
- Opaque child ciphertext cannot currently be causally matched to plaintext
  follow-up text without a stable correlation ID. Spawn falls back to the child
  thread and an unmatched follow-up remains unavailable rather than guessed.
- Rich replay is selected-root lazy but the reducer is synchronous and not yet
  cooperatively cancellable once replay has begun. Default event, event-size,
  and projected-node limits bound retained work; an individual line is still
  read by the standard buffered line reader before its size is rejected.
- Rich picker rows expose manifest-known metadata only; full status, counts,
  and runtime objects appear after selection.
- Content-level conflict detection beyond root/bundle identity remains a
  successor milestone.
- Search does not yet opt into raw-payload content, and causal edges/payload
  references are inspectable nodes rather than direct jump links.
- This receipt contains Linux validation only. macOS and Windows build evidence
  remains a release/CI prerequisite.
- Synchronized timelines, workflow diagnostics, live following, `/trace`,
  export, and annotations remain planned work.
