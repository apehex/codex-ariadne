# Ariadne trace browser plan

Date: 2026-07-25

Status: accepted project direction; milestones execute separately

## Desired state

An operator can launch `codex trace`, select a historical root session, follow
all delegated children, inspect turns and runtime actions at semantic or raw
levels, search the complete tree, and understand which facts are exact,
reconstructed, conflicting, or unavailable.

The result is useful on ordinary Codex rollouts and gains exact inference and
causal detail from explicitly enabled rollout-trace bundles. Operation is local,
offline, and read-only.

## Acceptance evidence

V1 is complete when:

- representative ordinary and rich root-child-grandchild sessions are
  navigable and searchable end to end;
- exact rich inference context and raw causal records can be opened lazily;
- unavailable encrypted or unrecorded evidence is labeled honestly;
- malformed records and missing payloads do not hide unaffected work;
- no trace, payload, state database, or archive file changes during browsing;
- the browser runs without authentication, network, or model configuration;
- Linux, macOS, and Windows builds pass with platform-neutral synthetic data;
- public fork, design, privacy, fixture, and upstream-participation
  documentation remains complete.

## Milestones

### 1. Fork and documentation bootstrap

- Establish `main` as the upstream mirror and `ariadne` as the rebased
  integration branch.
- Add fork identity, architecture, local agent rules, public-data policy,
  project history, and upstream issue draft.
- Establish deterministic synthetic fixtures as the only committed trace data.

Receipt: documentation links resolve, contains no private-origin references or
real trace material, and matches current upstream contribution policy.

### 2. Rich trace hardening

- Fix the known non-ASCII summary truncation panic in the rollout-trace reducer.
- Create synthetic rich bundles for inference, tools, compaction, terminals,
  code cells, and nested delegation.
- Run an opt-in Multi-agent V2 sentinel for spawn, follow-up, result, and close.
- If exact dispatch text is absent, add the narrow post-decryption trace event
  described in `DESIGN.md`.

Receipt: deterministic reduction never panics on arbitrary UTF-8 fixtures, and
the capability matrix states exactly which agent communications are observable.

### 3. Catalog and trace model

- Implement bounded root-session discovery and direct ID/bundle selection.
- Project ordinary rollouts and rich reduced state into one provenance-aware
  navigable model.
- Merge matching sources additively; expose contradictions and unavailable
  capabilities.
- Add stable locators, diagnostics, cancellation, and lazy raw payload access.

Receipt: model tests cover nested delegation, archived sessions, multiple
inferences, compaction, malformed records, cycles, orphans, missing payloads,
escaping paths, and source conflicts.

### 4. Historical TUI

- Wire `codex trace [SESSION_ID]`, `--bundle`, and `--trace-root`.
- Implement picker, adaptive browser, breadcrumbs, inspector, capability
  labels, and selected-root search.
- Sanitize raw text and preserve navigation on background-task failure.

Receipt: snapshot tests cover narrow, medium, and wide layouts; CLI integration
tests cover picker, direct selection, conflicts, and missing inputs.

### 5. Workflow diagnostics and timeline

- Add a synchronized cross-thread timeline.
- Surface unjoined delegation, interruption, failed tools, approval waits,
  unintegrated child results, compactions, and unusual resource consumption as
  evidence-backed diagnostics rather than inferred agent intent.

Receipt: each diagnostic has a synthetic positive and false-positive guard, and
opens the supporting nodes.

### 6. Live `/trace`

- Embed the stable browser model in the Codex TUI.
- Add app-server-backed incremental updates without weakening the offline
  historical path.
- Preserve the same source capabilities and inspector semantics.

Receipt: historical and live views render the same completed synthetic trace
equivalently, aside from explicitly transient state.

### 7. Observability extensions

- Propose recorder or app-server additions only for evidence gaps demonstrated
  by prior milestones.
- Keep opt-in sensitive capture separate from ordinary rollout behavior.
- Prepare each generalized addition as a small upstream-discussable change.

Receipt: every new persisted or protocol field is justified by a failing
observability scenario, versioned, bounded, and privacy-documented.

## Test matrix

Synthetic scenarios cover:

- root, child, and grandchild spawn/order/return;
- follow-up and peer messages;
- child success, failure, interruption, and close;
- several model generations within one turn;
- command, MCP, dynamic, code-mode, and collaboration tool lifecycles;
- compaction and replacement history;
- archived and incomplete sessions;
- encrypted and unavailable content;
- unknown record versions, malformed JSON, cycles, orphans, missing payloads,
  symlink/path escape, and terminal control characters.

Core test classes:

- unit tests for source projection, merge, locators, graph integrity,
  capability grades, search attribution, and sanitization;
- reducer and compatibility tests using deterministic rich bundles;
- Ratatui snapshots at representative terminal sizes;
- CLI tests for every supported selection route;
- an end-to-end mutation test that hashes all inputs before and after browsing;
- an offline test with authentication absent and network disabled.

## Deferred work

Exports, annotations, trace mutation, archive/delete operations, remote or cloud
traces, and a user-facing capture toggle are outside V1. Numeric performance
budgets are set after synthetic profiling, without relaxing bounded streaming,
lazy payload loading, or cancellation requirements.

## Decisions

- Fork Codex rather than build an external app-server client.
- Ship `codex trace` before `/trace`.
- Use existing ordinary rollouts and `codex-rollout-trace`; add no third schema.
- Keep the viewer offline and strictly read-only.
- Preserve source contradictions and explicitly label missing evidence.
- Carry only synthetic fixtures and public project history.
- Discuss upstream through an approved issue before any pull request.
